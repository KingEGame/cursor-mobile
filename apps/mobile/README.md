# Hermes Phone — mobile client (Expo / React Native, Android)

Client for the Hermes Gateway `phone_bridge` plugin (`server/phone_bridge`):
the phone pairs with the PC over LAN or Tailscale, then reads/sends ordinary
Hermes sessions stored in `~/.hermes/state.db` over REST + WebSocket `:8097`.

- Android package `local.hermes.phone`, app slug `hermes-phone`, deep links `hermes-phone://`.
- Screens: Pair, Sessions, Projects, Chat (live streaming), Settings.
- Photos/files: multipart, up to 10 files / 25 MB per message.
- Background: `modules/hermes-background` (Kotlin foreground service) keeps the
  bridge alive and pushes "session idle" notifications.

## Test / typecheck

```bash
# from repo root
npm test
npm run typecheck

# live E2E against a throwaway bridge (uses the app's own client code)
npm run e2e
```

## Pairing (one-tap)

The PC owner opens the bridge's `/pair` page (localhost-only) and approves the
phone's request — or the phone scans/enters the one-time code. Pairing requests
are created only on the PC.

## Local release APK

Sideload artifact, signed with the release key (same key CI uses for the
GitHub release):

```bash
npm run release:apk   # from repo root → dist-apk/hermes-phone-<version>.apk
```

The `android/` tree is generated by Expo and gitignored.

## Product locks

- PC-local + Tailscale reachability only — no port forwarding, no tunnels.
- `state.db` is the single source of truth; devices live in
  `~/.hermes/phone_bridge/devices.json`.
- No gateway core changes — everything is the `phone_bridge` plugin.
